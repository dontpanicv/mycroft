Same process means shared fate. A native crash can take the host and embedded agent down together. A JavaScript infinite loop can block the thread evaluating it. A JSContext is not an OS process or a hard CPU/memory quota.

Thread ≠ background permission. A thread or Swift actor organizes work within the process. The spike runs its small JS steps on @MainActor; a real host should keep expensive synchronous JS away from UI work. A worker thread still stops when iOS suspends the app.

Node.js is absent. Plain JavaScriptCore has no built-in Node fs, child_process, npm runtime, or browser DOM. Fetch, timers, module loading, and storage need host APIs or compatible adapters. TypeScript must become JavaScript before this host evaluates it.

Extensions are optional separate targets/processes. They have their own lifecycle and permissions. Our intent explicitly executes in the main app; adding an extension is not a persistent agent daemon.

Backend analogy: native process = service host; JSContext = embedded scripting environment; WebKit = another process reached through messages; app container = durable storage. “VM” here does not mean a Linux virtual machine.

Illustrates the tested generation-1 → generation-2 handover. Writing a file does not change functions already loaded into memory. The host must load the new source.


If iOS terminates the entire app: memory is lost → a later permitted launch starts a new native process → the host loads source + checkpoint. The agent cannot guarantee its own relaunch.


Persist data and explicit continuation state. An arbitrary call stack, pending promises, timers, native handles, and in-flight requests do not survive a JSON checkpoint. Production needs coordinated version activation/rollback; the spike writes source and state separately.

Two tested entry points, one agent host

 
Continued processingUser starts job → BGContinuedProcessingTask callback → Swift Runner → JavaScriptCoreSystem-granted time for a user-started job to continue after backgrounding. Reports progress; handles expiration/cancellation.

 
LongRunningIntentApp Intent → performBackgroundTask { Runner → JavaScriptCore }Extended execution for the intent. In this spike, the intent targets the main app process.




These APIs grant execution time; they do not create another JavaScript runtime. Neither turns the app into an unrestricted system service. An HTML screen is not required for the native host to run its agent.


Observed on your iPhone
Both paths completed 600 steps: 615.9 s and 621.7 s, including 589 background ticks each. Local reload worked before backgrounding. Reloading while already backgrounded remains unverified because the extra test could not launch.
The no-progress intent run was cancelled at 58.2 s with reason “unknown.” These observations establish finite execution, not 24/7 availability.


Suspension differs from screen lock. Locked-file access also depends on the file/Keychain data-protection class. Some OS-owned operations can continue while an app is suspended; that does not keep an arbitrary JS loop running.
