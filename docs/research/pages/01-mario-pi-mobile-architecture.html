The phone agent that builds itself: "Pi Mobile", now "p2", on Pi Durable

Reconstructed from about 350 of @badlogicgames's posts and replies (Sep 26 – Oct 17, 2026), plus the public earendil-works/pi repo. The app itself lives in the private pi-private repo, so the internals of the app are inferred from the libraries it is built on and from commit messages that mention it.

WhatA personal replacement for Claude/ChatGPT for Android. It has a web UI, multiplayer chat, subagents, artifacts, a file browser and git viewer, and works with any model provider.
Where it runsEverything except the LLM runs on his Pixel 11 (not rooted): the agent loop, tools, files, state and the web server.
Why it's possiblePi Durable commits every step to SQLite, so the processes can be killed at any moment (by Android, or by himself to reload code) and resume exactly where they stopped.
The recursionThe agent's working directory is the app's own source tree. Its edits trigger a hot reload or a worker respawn, and the conversation that made the edit carries on.

2 · The recursive loop: building pim with pim

Prompt from the phone

He types or dictates in the web UI, or a guest @-mentions the agent in chat mode, which turns all undelivered chat messages into one steering message.

Durable turn

The session worker commits the user entry, calls the LLM, commits the assistant entry, then runs tools as durable child tasks. Subagents and codemode scripts are themselves durable tasks.

The agent edits its own app

Its cwd is the pi-private checkout on the phone, so bash and edit tools change apps/p2 or the packages, then check, test and commit.

Reload

Frontend: Vite-style HMR, and the UI updates in place. Server, worker and plugin code: Chord hot reload (prepare → commit, drain then swap), or the process is simply killed and respawned.

Resume

The new process opens the same SQLite storage. Running tasks go back to pending, an interrupted LLM call is re-sent, replay-safe tools re-run and unsafe ones are marked interrupted. The conversation that triggered the reload just keeps going.

Use the new version

The next turn runs on the new code, because extension names are rebound to whatever is installed now. He has done this for about two weeks and rewritten the whole app twice, on the phone.

His one-line summary (Oct 3): "web > hmr. server/session workers > kill and respawn, pi durable takes care of the rest"

3 · How it evolved: three rewrites in about two weeks

v1 · Oct 3 · weekend hack
Termux + browser
Node server and session workers running in Termux, with the web UI on localhost in Chrome. Exposed via ngrok for multiplayer. He built it from inside regular pi running in Termux, then had it edit itself.
v2 · Oct 4 → 11 · "Pi Mobile" (apps/mobile)
Native Android APK
"No more termux needed": the APK bundles a Termux rootfs, Node and the pi-env daemon, and runs the monorepo from source. Added a file browser and git viewer, switching to a remote environment, agent messaging, networked hot-reloadable plugins, chat mode and durable codemode.
v3 · Oct 12 → now · "p2" (apps/p2)
Rebuilt on "chord2"
The host runtime (objects, cells, plugins, hot reload, memory/IPC/WebSocket links) was extracted from p2 into the public packages/chord. The old experimental server, client and protocol stack was deleted from public pi. There is no APK build for p2, and on Oct 16 he says the Termux process is kept alive, so it most likely runs in Termux again with the UI in a browser. On Oct 14: "designing a new plugin system. everything leads back to pi-durable concepts".
